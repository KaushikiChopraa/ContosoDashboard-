# Data Model: Document Upload and Management

## Document

Represents an uploaded work file and its searchable metadata.

| Field | Type | Rules |
|---|---|---|
| DocumentId | integer | Primary key; generated by the database |
| Title | string | Required; bounded length; searchable |
| Description | string? | Optional; bounded length; searchable |
| Category | string | Required; one of Project Documents, Team Resources, Personal Files, Reports, Presentations, Other |
| Tags | string? | Optional; normalized delimiter-separated tags; searchable |
| OriginalFileName | string | Display/download name only; never used as a storage path |
| FilePath | string | Required; unique generated relative path outside `wwwroot` |
| FileSize | long | Required; greater than zero and no more than 25 MB |
| FileType | string | Required MIME type; maximum 255 characters |
| UploadedDate | UTC datetime | Required |
| UploadedByUserId | integer | Required foreign key to User |
| ProjectId | integer? | Optional foreign key to Project |

Validation and access rules:
- The stored path uses the generated `{userId}/{projectId-or-personal}/{guid}.{extension}` shape.
- A document is readable by its owner, an administrator, current members of its project, or an explicit share recipient.
- Project managers may manage documents associated with their projects.
- Team shares for project documents resolve to current project members; Team Resources shares resolve to users with the selected department.

## DocumentShare

Represents explicit document access granted to a user or a team scope.

| Field | Type | Rules |
|---|---|---|
| DocumentShareId | integer | Primary key |
| DocumentId | integer | Required foreign key |
| SharedWithUserId | integer? | Optional individual recipient |
| SharedWithDepartment | string? | Optional department recipient for Team Resources |
| SharedByUserId | integer | Required actor foreign key |
| CreatedDate | UTC datetime | Required |

Exactly one recipient target is required. Duplicate active shares for the same document and target are rejected. Access is evaluated against current membership or department data.

## TaskAttachment

Associates an accessible document with a task.

| Field | Type | Rules |
|---|---|---|
| TaskAttachmentId | integer | Primary key |
| DocumentId | integer | Required foreign key |
| TaskId | integer | Required foreign key |
| AttachedByUserId | integer | Required actor foreign key |
| CreatedDate | UTC datetime | Required |

The attachment inherits the task's project context. The service rejects attachments when the document or task is not accessible to the requesting user, and prevents duplicate document/task pairs.

## DocumentActivity

Immutable audit record for governed document actions.

| Field | Type | Rules |
|---|---|---|
| DocumentActivityId | integer | Primary key |
| DocumentId | integer | Required foreign key or retained reference for delete audit |
| UserId | integer | Required actor foreign key |
| Action | string | Required; upload, download, preview, replace, edit, share, delete, attach |
| OccurredDate | UTC datetime | Required |
| Details | string? | Optional bounded context such as recipient or failure reason |

Administrators can query activity reports; non-administrators receive no report data.

## Relationships and lifecycle

- User 1-to-many Document uploads, DocumentShares, TaskAttachments, and DocumentActivities.
- Project 1-to-many Documents; Project 1-to-many existing ProjectMembers.
- Document 1-to-many DocumentShares, TaskAttachments, and DocumentActivities.
- Task 1-to-many TaskAttachments.
- Upload lifecycle: validate metadata/file -> authorize project context -> security scan -> generate unique path -> save file -> save metadata and audit row -> notify relevant users.
- Replacement lifecycle: authorize -> validate and scan replacement -> save replacement -> update metadata -> audit; failed replacement leaves the prior file and metadata unchanged.
- Delete lifecycle: authorize and confirm -> delete stored file -> remove metadata/relationships -> write retained delete audit record; stale links reveal nothing.
